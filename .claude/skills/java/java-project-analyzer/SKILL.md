# Java 项目分析与面试准备助手

## 概述

本技能用于快速理解和分析任意 Java 项目，并生成面向面试的深度准备材料。核心能力包括：项目全景分析、模块深度解析、面试文档生成。

## 工作流程

### 第一阶段：项目全景分析（首次触发自动执行）

当用户提到一个 Java 项目并希望分析时，按以下步骤执行：

1. **项目结构扫描**
   - 遍历项目根目录，识别项目类型（Maven/Gradle、单体/微服务、Spring Boot 等）
   - 读取 `pom.xml` 或 `build.gradle` 识别核心依赖和技术栈
   - 查找所有 `.md` 文档并建立索引

2. **文档优先阅读**
   - 优先阅读项目根目录下所有 `.md` 文件（README、架构文档、设计文档等）
   - 从文档中提取：项目背景、业务领域、架构概览、核心模块说明

3. **代码结构分析**
   - 识别源码目录结构（`src/main/java` 下的包结构）
   - 按包名推断模块划分和职责边界
   - 识别关键配置文件（`application.yml`、配置类等）

4. **输出全景分析报告**，包含：
   - **项目概览**：项目名称、业务领域、项目规模
   - **技术栈**：后端框架、数据库、中间件、核心依赖
   - **架构风格**：单体/微服务、分层架构/DDD/事件驱动等
   - **模块划分**：各模块名称、职责描述、依赖关系
   - **关键文档索引**：项目中重要的 md 文档列表

### 第二阶段：模块深度解析

当用户询问某个具体模块/功能的设计时，按以下框架深度分析：

1. **定位模块代码**
   - 根据模块名找到对应的包/目录
   - 阅读该模块的入口类、核心 Service、配置类

2. **四维度深度解析**

   **① 设计是怎样的（What）**
   - 类结构和核心接口
   - 关键设计模式的运用
   - 数据流向和调用链路
   - 与其他模块的交互方式

   **② 为什么这么设计（Why）**
   - 这样设计解决了什么问题
   - 背后的设计原则（SOLID、DRY、高内聚低耦合等）
   - 业务场景对设计的驱动因素

   **③ 有什么好处（Benefits）**
   - 可扩展性、可维护性、可测试性
   - 性能、可靠性、安全性方面的考量
   - 团队协作和开发效率的提升

   **④ 精妙点在哪（Cleverness）**
   - 设计中巧妙的地方（技巧性的实现、优雅的抽象）
   - 对边界情况的处理
   - 值得学习和借鉴的设计思想

3. **输出格式**
   - 先用一段话概括模块核心设计
   - 然后分四个维度展开
   - 结合具体代码片段或类名举例说明

### 第三阶段：面试准备文档生成

**首次使用本技能时，必须询问用户：**
> "是否需要为这个项目生成一份面试准备文档？包含项目亮点提炼、关键业务梳理、以及面向面试官追问的深度问答。"

如果用户回答"需要"，执行以下流程：

#### 步骤 1：项目亮点提炼

阅读项目文档和代码后，从以下角度提炼亮点：

- **技术亮点**：使用了哪些先进或巧妙的技术方案
- **架构亮点**：架构设计上的创新或优秀实践
- **业务亮点**：解决了哪些复杂的业务问题
- **性能亮点**：性能优化的关键手段
- **工程亮点**：工程化、代码质量、可维护性方面的亮点

输出 5-10 条最突出的项目亮点，每条用"亮点 + 具体实现 + 带来的价值"结构描述。

#### 步骤 2：关键业务梳理

列出项目中的 **6-10 个核心业务模块/功能**，让用户选择需要深入准备的部分。格式示例：

> 以下是项目中的关键业务模块，请选择你需要重点准备的（可多选）：
> 1. 用户认证与权限管理
> 2. 订单创建与支付流程
> 3. 商品搜索与推荐
> 4. 消息通知系统
> 5. 数据统计与报表
> ...

#### 步骤 3：深度面试问答文档

根据用户选择的模块，为每个模块生成一份深度面试准备文档。每个模块包含：

**【模块概述】**
- 一句话描述该模块的核心功能
- 在整体架构中的位置和作用

**【你负责的部分】**（引导用户结合自身经历）
- 建议从哪些角度描述自己的贡献
- 如何突出个人价值和技术深度

**【核心设计问答】**
- 5-8 个高频面试问题及参考答案
- 每个问题包含：问题 + 回答要点 + 追问方向 + 追问应答思路

**【设计深度追问准备】**
参考 [interview-deep-dive.md](references/interview-deep-dive.md) 中的追问框架，为每个模块准备：
- 为什么用这个技术方案，而不是其他方案？
- 如果并发量翻 10 倍，这个设计还撑得住吗？怎么优化？
- 有没有考虑过分布式场景下的一致性问题？
- 这个模块最容易出问题的地方在哪？怎么监控和告警？
- 如果让你重新设计，你会做哪些改进？

**【STAR 表达框架】**
为每个模块提供 1-2 个 STAR 结构的故事模板，帮助用户在面试中生动地讲述项目经历。

## 分析方法与工具

### 项目结构识别

使用 `glob` 和 `grep` 工具进行项目扫描：
- 识别构建文件：`pom.xml`、`build.gradle`、`build.gradle.kts`
- 识别配置文件：`application*.yml`、`application*.properties`、`bootstrap*.yml`
- 识别文档：`**/*.md`
- 识别源码包结构：`src/main/java/**/package-info.java` 或目录结构

### 技术栈推断

从依赖文件中提取关键技术：
- **框架层**：Spring Boot、Spring Cloud、MyBatis、JPA 等
- **数据层**：MySQL、PostgreSQL、Redis、MongoDB、Elasticsearch 等
- **中间件**：Kafka、RabbitMQ、RocketMQ、Dubbo、Nacos 等
- **工具层**：Lombok、MapStruct、Guava、Apache Commons 等

### 架构模式识别

根据代码结构和依赖判断架构风格：
- **分层架构**：controller/service/dao/mapper 经典分层
- **DDD 分层**：domain/application/infrastructure/interfaces
- **微服务架构**：多模块 + 服务注册发现 + 远程调用
- **事件驱动**：大量 event/listener/handler 模式

详细的架构分析方法见 [architecture-analysis-guide.md](references/architecture-analysis-guide.md)。

## 注意事项

1. **文档优先**：始终先读项目中的 md 文档，文档是最权威的设计说明
2. **代码验证**：文档中的描述需要用代码验证，避免文档过时导致误判
3. **不猜测**：无法确定的设计意图要明确标注"推测"，不要臆断
4. **面试真实**：生成的面试文档要引导用户结合真实经历，不鼓励编造
5. **深度递进**：面试问答从基础到深入，层层递进，模拟真实面试追问
