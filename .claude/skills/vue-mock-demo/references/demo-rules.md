# Demo 实战补充规则

本文件包含了一系列在开发 Mock Demo 时必须遵守的强制性规则，以确保代码质量和项目一致性。

## 页面与组件风格

1.  **风格对齐**：在开始开发新页面前，必须在当前项目中找到 1-2 个同业务域的已上线页面作为视觉和交互的“基线”。新页面的布局、间距、按钮样式等应与之保持一致。
2.  **组件统一**：同一个业务模块内，严禁混用不同技术栈的同类组件。例如，不能一部分页面使用 `a-table` (Ant Design Vue)，另一部分使用 `vxe-grid`。应统一使用项目主流方案。

## 数据与结构一致性

1.  **Mock 与表结构强一致**：`type.ts` 中定义的字段必须与用户提供的数据库表结构或接口文档逐项对应（包括字段名、类型、含义）。`mock.ts` 中的数据也必须完整覆盖这些字段，不允许出现“页面有，表里无”或“表里有，页面无”的情况。
2.  **路由与菜单检查**：新增页面后，必须进行一次三方对齐检查：
    *   **路由路径** (`path`)
    *   **组件路径** (`component`)
    *   **菜单来源** (本地路由文件 或 后端返回的菜单数据)
        确保三者完全匹配，特别是组件路径的大小写和目录层级。

## 最低验证清单

在交付 Demo 前，必须完成以下验证：

*   **页面可访问**：通过菜单或直连路由能正常进入页面，无 404 或空白页。
*   **页面可展示**：进入页面后，表格能成功加载并展示 Mock 数据，分页功能正常。
*   **页面可操作**：新增、编辑、删除、状态切换等核心功能至少各验证一次，确保流程通畅。
*   **页面可切换**：将 `api.ts` 中的 `USE_MOCK` 改为 `false` 后，页面代码无需任何修改即可准备对接真实接口。
